ACT 1 · 12 min Why Agent Quality Beats Cost (The Thesis)

Title & Agenda

Make every token count — optimize quality, and lower spend follows. Map of the 5 acts

Why This Matters

GitHub moved from premium requests → usage-based billing; cost-only focus diminishes Copilot's value

The "Gambling" Anti-Pattern

NASA analogy: fire 20 rockets at the moon, hope one lands — little context, lazy prompt, retry on fail

Why Gambling Broke

Fine at 2–4 agents/day; unsustainable at dozens–hundreds/day — and the cost now shifts to you

Make Every Token Count

Don't make the fuel cheaper (= keep gambling). Send fewer, higher-quality agents → fewer tokens automatically

The Compounding-Error Problem

99% accuracy/step × 50 steps = 61%; 95% × 50 = 8%. Every quality gain compounds your success odds

Reducing Context = Both Levers

Bloated context is re-paid every turn; trimming it improves quality AND cost at the same time

The Maturity Spectrum

~10 agents/day: low ROI on tuning. "AI engineer" with 100s of async agents: every % compounds

ACT 2 · 14 min Foundations — How LLMs, Agents & Context Windows Work
2A · LLM & Token Mechanics

Stateless Text Machines

LLM = word-probability, text-in/text-out; it has no memory of prior conversation

The Goldilocks Rule

"As little context as possible, as much as required" — the model can't tell relevant from irrelevant

Too Little → Hallucination

No error for missing info; the model fills gaps — "the math makes no distinction between fact & hallucination"

Agents, Harnesses & Models

Agent = app. Harnesses: VS Code Chat, CLI, Cloud Agent, Claude Code/Codex. LLM = GPT/Claude/Gemini

Re-Sent Every Turn

Each loop resends the full history: system prompt + tools + input + output (pricier). It compounds

Token Scale

1 token ≈ ¾ word. 50–200K small models, up to 1M large (≈ LOTR trilogy + The Hobbit)

1M Windows Aren't Free NEW JUN 3

Opt-in 1M-token windows (Opus 4.7, GPT-5.5) — GitHub's own warning: bigger windows = more credits; default recommended

2B · Two Context-Window Failure Modes KNOW THESE

Lost in the Middle

Model favors the start (instructions) + end (current work); switching tasks mid-session snaps it back → new window per task

Recency Bias

Above ~50% capacity it forgets system/original prompt & drifts — keep the window under ~60–70%

Silent Compaction NEW

VS Code auto-summarizes earlier messages when the window fills — "transparently in the background." Mid-session amnesia, explained; /compact + a disable setting exist

ACT 3 · 18 min The Billing Model — What Actually Gets Counted
3A · How Billing Works

The 2026 Shift NEW

June 1, 2026: premium-request units → usage-based GitHub AI Credits (1 credit = $0.01)

Credits = Tokens × Rate

Cost driven by input + output + cached tokens at each model's published API rate; above ~200–272K input a ~2× long-context tier kicks in

Cached Input = 90% Off NEW

Cache reads bill at 10% of input on every model; Anthropic adds a 1.25× cache-write premium. Stable prefixes pay — don't edit early instructions mid-session

Legacy Premium Requests

Still active for legacy annual Pro/Pro+ — both systems are live at once

What Counts as a Request LEGACY ONLY

Under legacy PRUs: your prompts count, the agent's tool calls do NOT. Under credits: every token meters — the biggest behavioral change

The Multiplier Table LEGACY

0.33× Haiku 4.5/GPT-4o · 1× Gemini 2.5 Pro · 6×/9× Sonnet 4.5/4.6 · 15×/27× Opus 4.5/4.7+ · 57× GPT-5.5 (raised Jun 1; verified Jun 9)

Plan Allowances VERIFIED JUN 9

Pro 1,500 · Pro+ 7,000 · Max 20,000 (new) · Business 1,900 / Enterprise 3,900 per user, pooled (promo 3,000/7,000 until Sept 1)

Code Review Bills Twice NEW JUN 1

Private-repo reviews consume AI Credits + Actions minutes (overage at standard rates); public repos exempt — a second meter nobody watches

3B · The Two Biggest Levers HIGH LEVERAGE

Right-Size the Model

50× input / 40× output spread (GPT-5.4 nano vs Fable 5; Opus-vs-mini ~16× blended). Reasoning models plan; small models implement

The Thinking-Effort Dial NEW JUN 2026

Model picker sets low/med/high reasoning per request (VS Code + JetBrains) — thinking tokens bill as output; right-size the reasoning too

Reasoning ≠ Always Better

On a tight spec a reasoning model second-guesses & "goes rogue" — use a lighter model to execute

Auto Model Selection

Now task-aware (not just availability) + a 10% token discount — well received

Base-Model Fallback CORRECTED

Gone under credits — exhaustion = stop, paid budget, or upgrade ("no automatic fallback to lower-cost models"); survives only on legacy annual

ACT 4 · 34 min Context Engineering — The Practical Controls (The Heart)
4A · Context Discipline DO THIS DAILY

New Task → New Session

/clear liberally; tokens don't carry across sessions, so throw away context without hesitation

Only Relevant Context

Don't pre-stuff "might need this"; let the agent discover files. Don't attach the whole codebase

Precise, Steering Prompts

"Fix the bug" ❌ → "Issue #45: XY happens, fix it" ✅. Tell it to STOP when tests pass; give known file paths

Compact Carefully

/compact loses info → misses/hallucinations; speaker prefers /clear + restart over compacting

4B · The Phased Workflow DO THIS DAILY

Research → Plan → Implement

A new context window per phase; don't carry research junk into implementation and pay for it every turn

Plan Mode + Reasoning

Use reasoning models in plan mode to produce a precise spec / to-do list — no room for variance

Parallel Agents by Layer

Split a clear spec by architecture layer, define contracts; each agent carries only its relevant context

Spec Kit OFFICIAL OSS

github/spec-kit formalizes the workflow: /speckit.specify → plan → tasks → implement; Copilot is the default integration. Quality lever, NOT a token saver (~20–40% more tokens, fewer wasted cycles)

4C · Deterministic Guardrails

Tests Are Context Engineering

Copilot CLI team ships ~500 PRs/week; #1 practice is tests — 50% of their codebase is tests

Reset the Compounding Error

A failing test is a deterministic gate — it stops a drifting agent and snaps accuracy back to ~99%

Beyond Tests

Linters, security scanners, code guardrails. No tests → stacked bugs → incidents (far higher total cost)

4D · Agent Config Taxonomy

Persistent Instructions

copilot-instructions.md / AGENTS.md are sent (and billed) on EVERY chat turn — keep tiny; path-scoped .instructions.md with applyTo globs load lazily

Write & Recreate Them

Don't AI-generate (speaky/imprecise); write from observed behavior; CLI team trashes theirs every ~3 months

Output Trimming

"Be concise, only return code" — output tokens are the most expensive (the "politeness costs millions" point)

Custom Agents

Manually-invoked roles (e.g. TDD-red); restrict tools to prevent wrong paths (read-only on a GitHub issue)

Skills

Like custom agents but loaded dynamically only on a matching task ("lazy context"); avoid redundant skills

MCPs, Sub-agents & Memory

MCPs bloat tool descriptions (scope Playwright into custom agents); sub-agents = 2nd window returning summaries; memory auto-learns

Copilot Spaces

Curate repos/files/PRs/notes once on github.com; questions bill as Chat requests by tokens — what's in the Space affects every question's cost

Delegate to the Cloud Agent

Runs in its own Actions environment, opens a PR — ~zero local context consumed; still bills credits + Actions minutes remotely. REST API (preview) for Pro+

4E · Power-User Tips

Think in Code

Write scripts to filter outputs before analysis — e.g. trim the GitHub REST API to relevant fields only

CLIs > MCPs

CLI tools like gh are already known to models and leaner than their MCP equivalents

Shell Output Trimming

Tools like RTK trim CLI output to agent-relevant info; VS Code now auto-compresses verbose terminal output (tests, builds, Docker) baseline

/chronicle

Analyzes your Copilot CLI session logs and suggests prompt optimizations

Collapse Tool Calls

Batch multiple tool calls into one to cut turns; model-specific tuning (power users w/ 1000s of agents only)

Utility Models

chat.utilityModel(+Small): route titles, summaries & commit messages to a cheap model — a capability, not a measured saving

ACT 5 · 15 min Verify, Monitor & Apply (Everyone)
5A · Verification & Monitoring Toolkit

Copilot CLI: /context

Visual breakdown — System/Tools, Messages, Free Space, Buffer; /compact to reclaim

IDE Context Gauges

Visual Studio ring + VS Code fill bar — hover shows exact tokens vs the model's window (e.g. 15K/128K) with per-category breakdown

The Debug Log

Inspect what was actually sent each turn and what was cached vs. not — manual but invaluable when learning

Org Dashboards & REST API

Premium-requests analytics (GA Sep 2025), usage/entitlements, billing API, CopilotPremiumUsageMonitor

5B · Putting It Together THE TAKEAWAYS

The 5 Headline Tips

Right model · precise prompts · split tasks (research→plan→implement) · deterministic guardrails · concise instructions

Cheat Sheet by Surface

Completions = free · Chat = right model · Agent = fresh sessions · CLI = /clear + /context

Future-Proofing Traits

Analytical/domain skills + good architecture (DDD, hexagonal, CQRS, event-driven) as agent guardrails
